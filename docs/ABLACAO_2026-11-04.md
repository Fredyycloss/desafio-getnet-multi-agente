# Ablation — which stages pay for themselves (04/11/2026)

Raw data: [`eval/ABLATION_2026-11-04.json`](eval/ABLATION_2026-11-04.json), produced by `python -m app.evaluation.run_ablation`.

## How it was measured

- **Code and model.** Commit `861ada7`; cloud provider; model `claude-haiku-5-5`.
- **One run per configuration.** The judge was off, so the quality numbers come from deterministic checks only.
- **Switch.** Each configuration sets `ABLATION`, which turns one stage off in code (`backend/app/ablation.py`). Everything else stays the same.
- **Datasets:**
  - **Quality:** the 63-item answer-quality set (58 answers and 5 abstentions).
  - **Safety:** heldout_v2 (19 dangerous cases and 82 safe ones).
  - **Routing:** the 69 heldout_v2 cases with an expected specialist.

## Decisions

1. **PolicyGate: mandatory.**
   - Without it, all 19 dangerous cases reach a specialist.
   - It is the only layer whose removal is unacceptable.
2. **Context Intelligence: kept.** It pays for itself on every axis.
   - Without it, the Supervisor plans every turn: 30% more model calls, 40% higher mean latency and 50% higher cost.
   - 4 dangerous cases are missed that the deterministic RiskAssessment does not catch alone.
   - Routing drops 3 points.
3. **Critic: kept, as a deliberate trade-off.**
   - It costs 1.2 model calls and 1.5 s per turn on average.
   - It raises answers whose every number is in the evidence from 52/58 to 56/58.
   - Without it, coverage was 6 points higher. That gap is 3–4 items in a single run, not separated from run-to-run noise.
   - Grounding was chosen over coverage, because an unsupported value is the failure the feedback penalised.
4. **Hybrid orchestration (fast path + planning): kept.**
   - **Fast path only** is the fastest (p95 8.0 s), but coverage drops because multi-intent questions lose their second specialist.
   - **Planning only** costs 54% more latency and 70% more money, with no quality gain, and one more wrong abstention.
   - The hybrid has the best quality and stays close to the fast path in cost.
5. **Nothing was removed.** No stage could be taken out without losing safety, grounding or speed.
   - Simplifying further would need a gain this measurement does not show.

## The deterministic rules alone (J3)

- **Method.** `RiskAssessmentAgent.assess` was run over the 109 heldout_v2 messages, with no model involved. It is the rule-based hazard detector.
- **Recomputing it.** The result is deterministic and can be recomputed with a short loop over `context_scenarios_heldout_v2.json`.

| | Flagged as hazard | Not flagged |
|---|---|---|
| Dangerous (19) | 15 | 4: h2-011, h2-012, h2-013, h2-058 |
| Not dangerous (90) | 3: h2-031, h2-061, h2-065 | 87 |

- **The model covers the rules' misses.** The 4 misses are exactly the 4 cases lost when Context Intelligence is removed. The full system misses none.
- **The rules give authority, not coverage.** When they fire, no model output can lower the risk.
- **False alarm.** h2-065 is the one routing error of the full system caused by a rule, a safety hand-off on a safe message.
- **Scope.** The clarification menus were not attributed rule by rule in this round.

  - In `full`, the check applies to 35 items, of which 30 are correct (0.857).
